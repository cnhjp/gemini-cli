# Gemini CLI 架构概览

本文档提供了 Gemini CLI 架构的高级概览。

## 核心组件

Gemini CLI 主要由两个主包组成，外加一套在系统处理命令行输入过程中使用的工具：

1.  **CLI 包 (`packages/cli`):**
    - **用途:** 包含 Gemini
      CLI 面向用户的部分，例如处理初始用户输入、呈现最终输出以及管理整体用户体验。
    - **包中包含的关键功能:**
      - [输入处理](/docs/cli/commands)
      - 历史记录管理
      - 显示渲染
      - [主题和 UI 自定义](/docs/cli/themes)
      - [CLI 配置设置](/docs/get-started/configuration)

2.  **Core 包 (`packages/core`):**
    - **用途:** 充当 Gemini CLI 的后端。它接收从 `packages/cli`
      发送的请求，编排与 Gemini API 的交互，并管理可用工具的执行。
    - **包中包含的关键功能:**
      - 用于与 Google Gemini API 通信的 API 客户端
      - 提示词构建和管理
      - 工具注册和执行逻辑
      - 对话或会话的状态管理
      - 服务器端配置

3.  **工具 (`packages/core/src/tools/`):**
    - **用途:**
      这些是扩展 Gemini 模型能力的独立模块，允许其与本地环境（例如文件系统、shell 命令、网络获取）进行交互。
    - **交互:** `packages/core` 根据 Gemini 模型的请求调用这些工具。

## 交互流程

与 Gemini CLI 的典型交互遵循此流程：

1.  **用户输入:** 用户在终端中输入提示词或命令，该输入由 `packages/cli` 管理。
2.  **向 Core 发送请求:** `packages/cli` 将用户的输入发送给 `packages/core`。
3.  **请求处理:** Core 包：
    - 为 Gemini API 构建适当的提示词，可能包括对话历史记录和可用的工具定义。
    - 将提示词发送到 Gemini API。
4.  **Gemini API 响应:** Gemini
    API 处理提示词并返回响应。此响应可能是直接回答，也可能是使用某个可用工具的请求。
5.  **工具执行（如果适用）:**
    - 当 Gemini API 请求使用工具时，Core 包准备执行它。
    - 如果请求的工具可以修改文件系统或执行 shell 命令，系统首先会向用户提供工具及其参数的详细信息，用户必须批准执行。
    - 只读操作（例如读取文件）可能不需要用户明确确认即可继续。
    - 一旦确认，或者如果不需要确认，Core 包将在相关工具内执行相关操作，并将结果由 Core 包发送回 Gemini
      API。
    - Gemini API 处理工具结果并生成最终响应。
6.  **响应 CLI:** Core 包将最终响应发送回 CLI 包。
7.  **显示给用户:** CLI 包格式化响应并在终端中向用户显示。

## 关键设计原则

- **模块化:**
  将 CLI（前端）与 Core（后端）分离允许独立开发和潜在的未来扩展（例如，同一后端的不同前端）。
- **可扩展性:** 工具系统设计为可扩展的，允许添加新功能。
- **用户体验:** CLI 专注于提供丰富且交互式的终端体验。
